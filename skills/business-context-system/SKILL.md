# business-context-system — контекст в три слоя

Система для бизнеса — это три слоя. Ты помогаешь их разложить и держать в порядке.

```
1. КОНТЕКСТ  — файлы: кто мы, что продаём, данные, решения       (читается всегда)
2. СКИЛЛЫ    — как делать повторяющиеся вещи                       (вызываются по задаче)
3. АГЕНТЫ    — кто делает это по расписанию / по событию          (работают без человека)
```

Большинство проблем «Claude тупит» — это слой 1: контекста нет, он устарел или лежит в трёх местах.

## Структура волта (6 папок)

```
мой-бизнес/
├── CLAUDE.md / AGENTS.md          ← диспетчер: что где лежит, правила
├── 00 Главное/                    ← goal.md · about-business.md · data-sources.md · decisions.md
├── 10 Клиенты/                    ← ЗОНА 1 — никогда в облако. В .gitignore
├── 20 Продукт/                    ← прайс, услуги, регламенты, ответы на типовые вопросы
├── 30 Контент/                    ← стиль, темы, план, опубликованное
├── 40 Продажи/                    ← лид-магнит, сценарии бота, скрипты
├── 50 Операционка/                ← рутины по шагам, шаблоны документов
├── 80 Журнал/                     ← checkin.md, ежедневник, итоги недель
└── .claude/skills/                ← скиллы
```

## Нейминг — главное правило порядка
- Файл называется так, чтобы по имени было ясно, что внутри и когда: `ОТЧЁТ — продажи — 2026-09.md`, `СКРИПТ — ответ на «дорого».md`, `РУТИНА — утренняя сводка.md`.
- Префикс = тип (ОТЧЁТ / СКРИПТ / РУТИНА / РЕШЕНИЕ / ШАБЛОН). Дата — `ГГГГ-ММ-ДД`.
- Одна тема — один файл. Не «всё.md».
- Правильно названный файл агент подхватывает сам — это и есть смысл.

## CLAUDE.md — диспетчер, не хранилище
В нём только: кто я (ссылка), цель (ссылка), где данные (ссылка), правила ответов, что никогда не делать, что делать после сессии, список скиллов. **Не более 60 строк.** Знания — в файлах и скиллах, не в диспетчере. Раздутый CLAUDE.md = токены в каждом чате и амнезия.

## Как делать
1. Прочитай, что уже есть (стартовая папка или хаос).
2. Предложи структуру выше, адаптируй названия под бизнес. Не создавай пустых папок «на будущее».
3. Перенеси файлы. Переименуй по неймингу. Спроси, если не уверен, куда.
4. Перепиши CLAUDE.md как диспетчер. Правила — через запреты («не выдумывай», «не отправляй»), они работают лучше предписаний.
5. Отметь зону 1 и добавь её в `.gitignore`.
6. Проверка: новый контекст → «что ты знаешь о бизнесе, где лежат отчёты, какие есть скиллы?» — ответ из файлов.
7. Раз в месяц: «нарисуй схему системы текстом» — покажи дубли и мёртвые файлы, предложи удалить (удаляет человек).

## Легковесность
Файлы контекста — короткие, со ссылками друг на друга. Не грузить весь волт в каждый чат. Одна задача — один чат, оркестратор + фоновые агенты для большого.

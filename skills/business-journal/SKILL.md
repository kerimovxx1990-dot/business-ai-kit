# business-journal — 3 строки в день, паттерны через 2 недели

Смысл: данные бизнеса — статика (отчёт раз в месяц). Самое интересное — между отчётами. Три строки в день дают это.

## Чек-ин (checkin.md)
Формат записи:
```
## 2026-10-06
- сделал по цели: …
- застрял: …
- заметил: …
```
Правила:
- Три строки. Больше — человек бросит через неделю. Минимум friction.
- Если человек пишет одну строку — принимай. Пустой день — пропускай, не ругай.
- Можно голосом: расшифруй и разложи в три строки сам.
- Один трекаемый параметр на период (число заявок / часы на рутину / опубликованные посты). Не пять.

## Через 14 записей — разбор
Прочитай `checkin.md` за период и ответь:
1. Что повторяется (день недели, тип задачи, время) — с примерами из записей.
2. Где «застрял» повторяется — это кандидат на скилл или на отказ.
3. Двигается ли цель из `goal.md` — по признаку, который там записан.
4. Одна рекомендация. Одна. С уровнем доверия — на 14 точках это C4, не выше. Не выдумывай корреляции: «по средам провал» на двух средах — не паттерн.

## Итоги недели (по пятницам или по запросу)
5 строк: сделано / не сделано / что заметил / решение на следующую неделю / одна вещь, которую убираем.
Записать в `80 Журнал/ИТОГИ — неделя ГГГГ-ММ-ДД.md`. Решения — в `decisions.md`.

## Чего не делать
- Не превращать чек-ин в анкету из 10 полей.
- Не делать выводов на 3 записях.
- Не предлагать «ещё трекать X, Y, Z». Один параметр, пока не войдёт в привычку.

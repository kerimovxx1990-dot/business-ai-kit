# business-deep-research — исследование, а не гороскоп

Цель: не «мнение модели», а документ, где у каждого вывода — источники, противоположная точка зрения и уровень доверия. И в конце — что конкретно делать в **этом** бизнесе.

Один запуск — один узкий вопрос. «Как расти» — не вопрос. «Стоит ли моей студии вводить абонементы вместо разовых» — вопрос.

## Вход
- Вопрос (одна строка).
- Контекст: `about-business.md`, `goal.md`, свежие данные из `data-sources.md`, если относятся.
- Режим: `consensus` (что вообще известно) или `personal` (что делать именно нам). По умолчанию — оба.

## Пайплайн (запускай этапы как отдельных субагентов, если среда умеет; иначе — по очереди в одном контексте)

### 1. SOURCES — собрать
3–4 поиска в разных стилях: прямой («X в малом бизнесе результаты»), контрарный («почему X не работает»), практический («кейс X ниша Y»), свежий (последние 12 месяцев). Инструменты: web search, fetch страниц. Каждый источник: ссылка, дата, кто автор, **кто платит** (продавец инструмента / независимый / участник рынка).
Собери 8–15 источников. Не больше — дальше шум.

### 2. CRITIC — где ломается
Для каждого ключевого утверждения: при каких условиях не сработает, для какого размера бизнеса, что противоречит. Отдельно: что в источниках — реклама.

### 3. CONSENSUS — что известно вообще
Короткий свод: где источники сходятся (C2), где один источник (C3), где спор. Без привязки к нашему бизнесу.

### 4. PERSONAL — считай относительно нас
Наложи на `about-business.md` и данные: наш размер, ниша, канал, что уже пробовали. «Считай относительно моего бизнеса, не в среднем». Что из консенсуса к нам не применимо и почему.

### 5. FACT-CHECK — цифры
Топ-5 чисел из документа: перепроверь по источнику дословно. Не нашёл — помечай C5 или убирай.

### 6. ACTION MAPPER — что делать
3–5 действий: что, когда, как поймём, что сработало (метрика), через сколько проверить (retest). Каждое — с уровнем доверия. **Изменения в файлах волта — только после «да» человека.**

### 7. DECISION LEDGER
Спроси по каждому действию: делаем / не делаем / позже. Запиши в `decisions.md` с датой и причиной. «Не делаем» тоже записывается — чтобы не предлагать снова.

## Выход — один файл `ИССЛЕДОВАНИЕ — <вопрос> — ГГГГ-ММ-ДД.md`
```
# Вопрос
# Короткий ответ (5 строк, с уровнем доверия)
# Что известно (консенсус)          — C2/C3 по пунктам
# Где ломается (критика)
# Относительно нас                  — что применимо, что нет
# Действия                          — что / метрика / retest / доверие
# Источники                         — ссылка · дата · кто платит
# Что не проверено
```
Объём — 1–3 страницы. Не 20.

## Уровни доверия
C1 проверено на наших данных · C2 несколько независимых источников · C3 один источник / отраслевое правило · C4 предположение модели · C5 догадка = вопрос.

## Правила
- Не выдумывать источники. Нет ссылки — нет утверждения.
- «Кто платит» — обязательно у каждого источника.
- Не давать юридических/налоговых/медицинских заключений — только «что спросить у специалиста».
- Если вопрос слишком широкий — сначала сузить, спросить человека.
- Скилл в чате без web search работает частично (только знание модели) — честно предупреди, что уровень доверия не выше C4.
